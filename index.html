Task 1: Drawing Single-Color Triangles

Raterizing triangles involves checking points on the image and seeing if a given point is inside of the triangle. These points correspond to the center of pixels, determining if they should be filled in the frame buffer. This is acheieved by doing 3 line tests that determine if the point is all above the lines going either clockwise or counterclockwise, since the intersection of the 3 planes mark the area of the triangle. However, it would be very inefficient to check every single point for every single triangle, which is why we often will only consider the bounding box where the triangle lies. My code achieves this by first looking at the minimal and maximal x and y values and iterating through the points strictly within this box.

Task 2: Antialiasing by Supersampling

Data Structures: I used the data structure of a vector of floats in order to store the sum of color values from subpixels for a given pixel. I probably could've just used the Color class as a data strucutre for this but a vector was just another very natural representation for 3 color channels. I also manipulate the sample_buffer, which has an underlying data structure of a vector of Colors. My (super)sampling involves writing and reading Colors by indexing into this vector for O(1) access for the many times I needed to index into the buffer. The rgb_framebuffer_target I eventually write into is a pointer to an unsigned char, which is there to hold each color value as a 1 of 256 possibilies (for 1 byte in a char, 2**8 possibilies), so functionally a vector who's values range from 0-255, minimizing the amount of memory taken to represent a color channel.

Algorithms and Explanations: My algorithm for supersampling starts in rasterize triangle by filling the sample buffer with samples of the image at a higher frequency. Specifically for each "real" pixel, sample_rate number of subpixel samples are filled into sample_buffer contigously (for easier access later on). The center of the subpixel sample is determined by taking the top left corner of the subpixel and offsetting the x and y positions by exactly 0.5/sqrt(sample_rate), which gives the middle of each subpixel. Then, in resolve_to_framebuffer, each step in the double iteration loop increments by sample size, and then the previously placed contigous subpixels are averaged to give the final pixel value. This final pixel value is then written to the framebuffer. This algorithm greatly modifies the rasterization pipeline. Wheras previously one pixel in the frame buffer represented one pixel in the sample buffer, now one pixel in the frame buffer is the average of several pixels in the sample buffer, so the rasterization pipeline was altered dramatically to include both the supersampling mentioned in the algorithmic description and the averaging of the supersampled subpixels. Additionally, the size of the sample buffer needed to change w.r.t to the sampling rate, so whenever the size of the frame buffer changed, the size of the sample buffer changes x times as much where x is the sampling rate.

Supersampling is very useful as a tool to combat aliasing. In the case of this problem, it helped reduce the amount of "jaggies" of the triangles making the edge look smoother and more like a straight edge. It does this by having pixels that are partially in the triangle to also appear colored w.r.t. the amount they are inside the triangle, creating a blur effect. Another case were supersampling with downsampling is useful for anti-aliasing to act as a low-pass filter, which can ensure that higher frequency features do not alias and appear as fake lower frequency features when sampled below the Nyquist frequency.

Task 4: Barycentric coordinates

Barycentric coordinates (in the context of triangles for this class) are a coordinate system defined with respect to points, where each coordinate value dictates how close a given point is to the predefined points (which in our case would be corners of a triangle). Mathematically a point P in the x,y plane is defined by P = alpha * A + beta + B + gamma * C, where A, B, C are the points of the trinagle in x,y coordinates.

Each barycentric coordinate is also equal to the area of the opposing triangle (triangles defined by drawing lines from each vertex to the point in the triangle) divided by the total area of the larger triangle. The values of barycentric coordinates are also normalized: they sum to 1.

Task 5: "Pixel sampling" for texture mapping

Pixel sampling for texture mapping is neccesary since often the size of each pixel does not represent exactly one texel, so some decisions have to be made on which texel gets to represent that pixel. There are two types of pixel sampling for this task: nearest, which just samples the texel that is closest to the center of the corresponding uv coordinate, and bilinear, which linearly interpolates in both the u and v direction (hence bilinear) in order to obtain a weighted average of 4 texels that better represents the pixel's color. I implemented these sampling methods by converting my sx and sy subpixels into uv coordinates using barycentric coordinates and then setting the color to the result of the nearest/bilinear sampling on the texture.

There are some notable differences, nearest in some cases will not take in as much information as bilinear, however nearest also does not blur texels together, which can be useful for pixel art or trying to maintain the readability of text. The differences are most apparent when the image is a very different size than the texture. Task 6: "Level Sampling" with mipmaps for texture mapping

Level sampling refers to sampling different mipmap levels depending on how large a pixel is compared to a texel. It seeks to try and even the sizes between the two, so information is not lost when the pixel would've been too big to capture all the texels it covers. I used level sampling by computing the change in u and v in the texture for each adjacent pixel and selecting the level corresponding to how much change going to the next pixel/subpixel would cause (thus computing the size of each pixel relative to a texel).

The three techniques used for level sampling were linear, nearest, and zero. Zero is the default and simplest, sampling from the original texture. Linear on the other hand does another lerp between two levels of mipmap since it's possible that our pixel is between two sizes of mipmaps. Nearest on the other hand just goes to the mipmap representation that is closest in terms of pixel/texel size.

Supersmapling remains the most computationally expensive of the techniques implemented. Every time the supersampling rate increases, the amount of subpixels that need to be looked at increases by that same factor (16x supersampling = 16x more subpixels). It is slow, but theoretically it can use not much more memory since you could discard subpixel results as soon as they are averaged into the frame buffer. If this isn't done however, memory usage also scales linearly based on supersampling rate. When you really crank up the sampling rate, it is the most powerful for resolving edges and reducing jaggies, and can work without textures.

Bilinear interpolation and layer sampling (nearest/linear) on the other hand apply to textures, and are less computationally expensive. They also don't require much more memory, with the mipmaps needed for both forms of layer sampling and bilinear interpolation being only a small constant multiple larger than the original texture map. Bilinear interpolation is fast, since it doesn't need to point in triangle tests unlike supersampling. Layer sampling is relatively cheap since, besides some overhead compute to find derivatives, it just reads from a precomputed mipmap, and does only a single extra lerp + read in the case for level= linear. These texture sampling techniques can be very effective for anti-aliasing in certain circumstances, when the texel and pixel sizes are very mismatched (like if an object is very far away), since the lower resolution mipmaps effectively supersample the larger level 0 texture.
